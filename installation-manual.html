1. Architectural Stack Overview

AgriTrace is built upon an ultra-fast, serverless, modular architecture that requires zero heavy build toolchains:

🌐 HTML5 Semantic UI 🎨 Vanilla CSS3 Design System ⚡ Native JavaScript ES Modules 🔥 Firebase Authentication v10.8 📦 Cloud Firestore Real-time NoSQL 🛡️ Role-Based Security Rules 🇦🇺 Australian Context & AUD Pricing

Because all application logic runs via standard browser ES Modules, there are no complex Webpack, Vite, or bundle dependencies required to run or evaluate the platform locally.

2. System Requirements & Prerequisites

  • Modern Web Browser: Google Chrome, Mozilla Firefox, Microsoft Edge, or Apple Safari (supporting ES Modules and CSS Grid).
  • Local HTTP Server (any of the following):
    • Python 3.9+ (included in most environments)
    • Node.js 18+ (with npx)
    • VS Code with the Live Server extension
  • Google Firebase Account: Free Spark or Blaze plan for Cloud Firestore and Authentication.

3. Firebase Project Setup

Follow these steps in the Firebase Console:

  1. Click Add Project, enter a name (e.g., agritrace-australia), and complete creation.
  2. Navigate to Build → Authentication. Click Get Started and enable Email/Password sign-in provider.
  3. Navigate to Build → Firestore Database. Click Create Database, choose Production mode, and select a regional location (recommended: australia-southeast1 Sydney).
  4. In Project Settings, register a Web App (</>) to obtain your Firebase credentials.

4. Project Configuration

Open js/firebase-config.js and verify your Firebase configuration object:

import { initializeApp } from "https://www.gstatic.com/firebasejs/10.8.1/firebase-app.js"; import { getAuth } from "https://www.gstatic.com/firebasejs/10.8.1/firebase-auth.js"; import { getFirestore } from "https://www.gstatic.com/firebasejs/10.8.1/firebase-firestore.js"; const firebaseConfig = { apiKey: "YOUR_API_KEY", authDomain: "YOUR_PROJECT.firebaseapp.com", projectId: "YOUR_PROJECT_ID", storageBucket: "YOUR_PROJECT.appspot.com", messagingSenderId: "SENDER_ID", appId: "APP_ID" }; export const app = initializeApp(firebaseConfig); export const auth = getAuth(app); export const db = getFirestore(app);

5. Firestore Security Rules Deployment

To enforce role-based access control and admin authorization, copy the contents of firestore.rules into the Firebase Console Rules editor:

rules_version = '2'; service cloud.firestore { match /databases/{database}/documents { function isAdmin() { return get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'admin'; } function getRole() { return get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role; } // Users Collection: Admin can approve/update any user match /users/{userId} { allow read: if request.auth != null; allow create: if request.auth != null && request.auth.uid == userId; allow update, delete: if request.auth.uid == userId || isAdmin(); } // Products & Orders Collections match /products/{productId} { allow read: if request.auth != null; allow create, update, delete: if getRole() == 'farmer' || isAdmin() || getRole() == 'customer'; } match /orders/{orderId} { allow read: if request.auth != null; allow create, update: if request.auth != null; allow delete: if isAdmin(); } } }

7. Running Locally

You can run the platform locally using any of these simple methods:

Method A: Windows Run Batch File (Recommended)

Double click run.bat in the project root folder. It automatically detects Python or Node.js and starts the server on port 8000.

Method B: Python Built-in HTTP Server

python -m http.server 8000

Method C: Node.js HTTP Server

npx http-server -p 8000 -c-1

Method D: Visual Studio Code

Right-click index.html inside VS Code and choose "Open with Live Server".

8. Production Deployment Options

Because AgriTrace is 100% static client-side with cloud backends, it can be deployed on any static hosting provider:

  • Firebase Hosting:
    npm install -g firebase-tools firebase login firebase init hosting firebase deploy
  • GitHub Pages / Netlify / Vercel: Simply connect your Git repository and set the root directory as the publish directory.
